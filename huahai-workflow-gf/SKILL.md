# Git Flow（gf）

自动化 git 工作流：状态 → 暂存 → 提交 → 拉取 → 推送，适配任意宿主 Agent。全程自动执行、不再逐步询问用户；提交信息按变更内容自动生成。

---

## 归档开关（先于流程判断，全局生效）

扫描**本轮用户提示词**（含 `/gf`、提交代码、推送等触发句）是否提及归档意图，判断结果在回复中写明一行，如 `归档：是（推送后执行）` 或 `归档：否（仅提交推送）`。

| 提示词 | 行为 |
|--------|------|
| **含**归档措辞（`归档`、`一并归档`、`发布并归档`、`gf 并归档`、`提交并归档`、`推送并归档`、`archive`明确指 workflow 归档） | git 全流程**之后**执行「归档」 |
| **不含** | **只**做 git 流程，**禁止**归档、**禁止**删除 `todolist.md` |

不算归档意图：业务文案里的「合同归档」「归档库」等且未要求整理 grillme；单独说「归档」而未触发 gf → 不走本 skill，应由 `huahai-workflow` 步骤6 处理。

后续各步骤不再重述开关，一律按此判断执行。

---

## 执行流程

### 1. 检查状态（自动）

```bash
git status
```

- 有未跟踪 / 已修改未暂存文件 → 列出，继续
- 工作区干净 → 终止流程（若本轮要求归档且仅有 grillme 待整理，可单独做归档，仍须提示词含归档）

### 2. 暂存（自动）

暂存前同步 `.gitignore`：若规则存在但文件仍被跟踪，先从缓存移除（不删本地文件）：

```bash
git ls-files -i --exclude-from=.gitignore   # 有输出则继续下行
git rm --cached <上述列出的文件>
git add -A
```

`todolist.md` 若在 `.gitignore` 中，不要强行入库。暂存后再跑一次 `git status` 确认。

### 3. 提交（自动）

```bash
git diff --cached --stat          # 据此判断变更类型
git commit -m "<自动生成的提交信息>"
```

**提交信息规则**（conventional commits，中文/英文均可）：

- subject ≤50 字符，祈使语气，结尾不加句号
- 按变更选前缀：`feat` / `fix` / `docs` / `refactor` / `style` / `test` / `chore`
- 单文件取功能名，多文件归纳整体目的
- **禁止添加 `Co-Authored-By:` 或任何 AI 归因尾注** — 内网环境敏感

**粒度**：一个 commit 对应一个子任务；1-8 文件、50-300 行为宜，超过 500 行拆分；每个 commit 须能编译通过或过项目既有验证。

### 4. 拉取（自动）

```bash
git pull origin <当前分支>
```

冲突 → 显示冲突文件、暂停、等用户手动解决。**未推送成功前不执行归档**。

### 5. 推送（自动）

```bash
git push origin <当前分支>
```

### 6. 归档（仅当开关为是）

前置：开关为是，且步骤 5 推送成功（若本轮无代码变更、仅归档，跳过 1-5 中无意义步骤，仍须提示词含归档）。

对齐 `huahai-workflow` 步骤6：

1. 从 `todolist.md` 读 `doc_root`（无则用用户指定或默认 `yqsz/docs/grillme`）
2. 创建 `<doc_root>/archive/YYYY-MM-DD-<feature>/`（重名则 `-2`、`-3`…）
3. 移入 `adr/`、`specs/`、`tickets/` 下当前任务产物（**`CONTEXT.md` 留项目根**）
4. 删除项目根 `todolist.md`
5. 若归档产生入库路径变更（如 `specs/` → `archive/...`），再走一轮简短 git：暂存 → 提交（`docs: 归档 <feature> grillme 产物`）→ 拉取 → 推送

---

## 特殊情况

- **无变更**：未要求归档 → 提示后终止；要求归档 → 仅执行步骤6，完成后若有文件移动再提交推送归档 commit
- **分支不存在**：列出可用分支，询问用户选择

---

## 快捷用法

| 用户输入 | 执行 |
|---------|------|
| `/gf` | 仅 git 全流程（不归档） |
| `/gf` 且提到归档 | git 全流程 + 归档 |
| `git flow` / `提交代码` / `推送代码` | 同 `/gf`；提示词含归档则追加归档 |

---

## 注意事项

- 在 git 仓库目录下执行；确保有远程仓库连接
- 暂存前自动同步 `.gitignore`，确保被忽略文件不被提交
- 与 `huahai-workflow` 一致：**gf 不暗含归档**，只有用户写明归档才做
